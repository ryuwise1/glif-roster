# 'GLIF Network 서버' 시트와 쌍방 동기화

'GLIF Network 서버' 시트의 연명부 탭과 사이트 연명부를 서로 맞춥니다. **사이트가 기준입니다.**

## 동작

- **사이트 → 시트 (10분마다)**
  - 연명부 탭의 학회원 줄을 사이트 내용으로 통째로 다시 씁니다.
  - 한 줄은 한 사람의 한 경력입니다. 현직은 구분(정규·인턴 등)과 상관없이 모두 넣고, 이전 직장은 정규직만 넣습니다. 이전 직장 줄은 옅은 글씨로 칠합니다.
  - 경력이 없는 사람도 한 줄로 나옵니다.
  - 순서: 기수 → 회장·부회장 → 이름. 한 사람 안에서는 현직 먼저, 그다음 최근 이전 직장 순입니다.
  - 본인이 사이트에서 숨긴 휴대폰·개인 이메일은 `비공개`로 나옵니다.
  - 비학회원 줄(기수 칸이 `비학회원`)은 사이트에 없으므로 시트에 있던 그대로 맨 아래에 둡니다.
  - L열 `학회원 ID`, M열 `경력 ID`는 숨긴 칸입니다. 고치지 마세요.
- **시트 → 사이트 (고칠 때마다)**
  - 시트에서 칸을 고치면 그 줄을 바로 사이트에 반영합니다.
  - 시트에서 고칠 수 있는 칸: 학번(A), 직장명(D), 부서명(E), 직급(G), 직무(H), 휴대폰(I), 개인 이메일(J), 구분(K: `현직`/`이전`)
  - 직무는 사이트 목록에 있는 값만 됩니다: 주식, 채권, S&T, IB/PE, 리서치, 운용, 영업, 재무, 기타
  - 새 경력 추가: 빈 줄에 기수(B)·성함(C)을 사이트와 똑같이 적고 직장명(D)을 적으면 정규 경력으로 들어갑니다. 구분을 `이전`으로 적지 않으면 현직으로 들어갑니다.
  - 반영되지 않은 줄은 학번 칸에 메모로 이유가 남고, 화면 오른쪽 아래에 알림이 뜹니다.

## 시트에서 할 수 없는 것

- 기수·성함·기수 역할 바꾸기, 학회원 추가: 사이트 관리자 화면에서 합니다.
- 경력 지우기: 사이트에서 지웁니다. 시트에서 줄을 지워도 10분 안에 다시 생깁니다.
- 연락처(F) 직접 고치기: 휴대폰 → 개인 이메일 → 직장 이메일 중 처음 있는 값으로 자동으로 채워집니다.
- 직장 이메일, 업종, 지역, 시작·끝난 달: 시트에 칸이 없습니다. 사이트에서 고칩니다.
- 위 칸을 시트에서 고치거나, 반영되지 않은 줄은 10분 안에 사이트 값으로 돌아갑니다.

## 주의

- **시트 편집 권한이 곧 사이트 수정 권한입니다.** 시트를 고칠 수 있는 사람은 모든 학회원의 학번·휴대폰·개인 이메일·경력을 고칠 수 있습니다. 시트 편집자는 Apps Script 의 스크립트 속성(동기화 키)도 볼 수 있습니다.
- 시트에서 고친 내용은 사이트의 수정 기록에 "누가"가 비어 있는 채로 남습니다.
- 처음 `pullFromSite`가 돌면 연명부 탭의 학회원 줄이 사이트 내용으로 바뀝니다. 그 전에 지금 탭을 복사해 두세요. 2026-10-22 에 만든 `연명부(10-22 백업)` 탭이 있습니다.

## 설정 (한 번만)

1. **DB 마이그레이션 적용**: `supabase/migrations/20261022000009_sheet_sync.sql`
2. **동기화 키 만들기**
   - Supabase SQL 편집기에서 아래를 실행합니다.
   - 결과로 나온 `sync_key` 값을 복사해 둡니다. DB에는 이 값의 해시만 남습니다. 드라이브 동기화 키와 다른 키입니다.
   ```sql
   with k as (select replace(gen_random_uuid()::text || gen_random_uuid()::text, '-', '') as key)
   insert into public.sync_keys (name, key_hash) select 'sheet', encode(sha256(convert_to(key, 'UTF8')), 'hex') from k
   on conflict (name) do update set key_hash = excluded.key_hash
   returning (select key from k) as sync_key;
   ```
3. **Apps Script 만들기**
   - 'GLIF Network 서버' 시트에서 확장 프로그램 → Apps Script 를 엽니다.
   - `Code.gs` 내용을 붙여 넣고 저장합니다.
4. **스크립트 속성 넣기** (프로젝트 설정 → 스크립트 속성)
   - `SUPABASE_URL`
   - `SUPABASE_PUBLISHABLE_KEY`
   - `SYNC_KEY`: 2단계에서 복사한 값
5. **실행하기**
   - 편집기에서 `pullFromSite`를 한 번 실행합니다. 권한을 허용하고, 실행 기록에 "사이트 → 시트"가 나오는지, 연명부 탭이 바뀌었는지 봅니다.
   - 이어서 `installTriggers`를 한 번 실행합니다. 이후 10분마다 내려받고, 고칠 때마다 올립니다.
   - 트리거는 실행한 사람의 계정으로 돕니다.

## 키를 바꾸거나 끄려면

- **키 바꾸기**: 2단계를 다시 실행하고, 4단계의 `SYNC_KEY`를 새 값으로 바꿉니다.
- **동기화 끄기**: Apps Script 편집기의 트리거 화면에서 두 트리거를 지우고, SQL 편집기에서 아래를 실행합니다.
  ```sql
  delete from public.sync_keys where name = 'sheet';
  ```
